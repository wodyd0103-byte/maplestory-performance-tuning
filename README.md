# 메이플스토리 다중 게임 동시 실행 성능 진단

메이플스토리 · TFT · FC ONLINE · Chrome 을 동시에 돌릴 때 발생하는 **프리징(멈춤)** 과 **프레임 드랍(끊김)** 을 성능 카운터로 측정해 원인을 분리하고, 해결한 기록.

추측 대신 **측정값으로 판단**하는 것을 원칙으로 했다. 그 과정에서 틀린 가설도 여럿 나왔고, 그것도 그대로 남겼다.

📖 **[진단 여정 — 상세 기록](docs/troubleshooting-journey.md)** — 증상 신고부터 원인 확정까지 9단계를, 각 단계의 가설·측정값·오판과 함께 시간순으로 정리한 문서. 결론만 필요하면 아래를, 과정이 궁금하면 그쪽을 보면 된다.

---

## 결론 요약

| 증상 | 원인 | 상태 |
|---|---|---|
| **프리징 (수 초간 멈춤)** | 물리 RAM 부족 → 페이지파일 스와핑 | ✅ **해결** (RAM 32GB → 64GB) |
| **프레임 드랍 (끊김)** | P코어 6개 vs 게임 3개 (CPU 구조적 한계) | ❌ 미해결 |

핵심 수치 하나: **시스템 커밋 36.6GB > 물리 RAM 31.8GB**. 이게 프리징의 전부였다.

## 2. 측정 방법

PowerShell 성능 카운터를 2초 간격으로 폴링해 CSV로 기록. (`scripts/loadlog.ps1`)

수집 항목:

- `\Processor(*)\% Processor Time` — 전체 및 **코어별** 사용률
- `\Memory\Pages Input/sec` — **하드 페이지 폴트** (프리징 직접 지표)
- `Win32_PageFileUsage` — 페이지파일 실사용량
- `\GPU Engine(*)\Utilization Percentage` — 엔진별(3D/VideoDecode/Copy/…) 분리
- 앱별 WorkingSet / GPU 점유

### 지표 선택이 결정적이었다

처음엔 `페이지파일 사용률 %`(할당량 대비 비율)를 봤고 평탄해서 **"스와핑 없음"으로 오판**했다. 이건 *할당량* 지표지 *발생률* 지표가 아니다.

올바른 지표는 **`Pages Input/sec`** 과 **`Win32_Process.PageFileUsage` vs `WorkingSetSize` 격차**다. 이걸로 바꾸자마자 원인이 드러났다.

## 4. 프리징 메커니즘

```
게임 3개 커밋 합계 36.6GB  >  물리 RAM 31.8GB
        ↓
Windows가 백그라운드 앱 워킹셋을 페이지파일로 축출
        ↓
MapleStory: 커밋 12.5GB 중 상주 2.4GB (10GB가 디스크에)
        ↓
다른 게임 보다가 메이플로 복귀
        ↓
축출된 10GB를 NVMe에서 되읽기 = 하드 페이지 폴트 폭주 (초당 최대 607건)
        ↓
수 초간 멈춤 = 프리징
```

RAM 접근 ≈ 60~80ns, NVMe 페이지 폴트 ≈ 50~100µs. **약 1000배 차이.**

### 왜 64GB가 해결하는가

RAM이 넉넉하면 축출된 페이지가 **페이지파일이 아니라 대기 목록(standby list, RAM 내부)** 에 남는다. 되읽을 때 디스크가 아니라 RAM에서 가져오므로(소프트 폴트) 멈춤이 없다.

메모리 압박이 있을 때만 대기 목록이 재활용되고, 그때부터 하드 폴트가 된다.

## 5. 폐기된 가설들

측정으로 반증된 것들. 같은 실수를 반복하지 않기 위해 남긴다.

| # | 가설 | 반증 근거 |
|---|---|---|
| 1 | "작업관리자 수치 오독일 것" | 4개 동시 실측 결과 RAM 88.3%, CPU 81% — **사용자 관찰이 정확했다** |
| 2 | "메모리 누수 아님, 5.6GB에서 평탄화" | 장시간 측정 시 8.7GB까지 증가. **시간당 약 3.7GB** |
| 3 | "스와핑 0, RAM 증설 불필요" | **잘못된 지표**를 봤음. `Pages Input/sec` 로 재니 초당 최대 607건 |
| 4 | "메이플이 E코어에 밀려서 튄다" | P코어 고정(CPU 0,2,4,6) 후 재측정 → **개선 0**. E코어를 태우는 건 TFT·FC온라인 |
| 5 | "크롬 스트리밍의 GPU 디코드가 범인" | `GPU VideoDecode = 0.0%` 전 구간. 크롬 CPU도 1% 미만 |

### 특히 4번 — 검증 방법

가설을 검증하려면 메이플을 P코어에만 배정해봐야 했다. 그런데 실행 중인 메이플 프로세스는 선호도 변경이 거부된다:

```
Exception setting "ProcessorAffinity": "Access is denied"
```

메이플의 안티치트(nGuard)가 프로세스 핸들 권한을 제한하기 때문이다. 작업관리자에서도 동일하게 거부된다.

대신 **Windows가 프로세스 생성 시 부모의 선호도를 자식에게 물려주는 기본 동작**을 이용했다. 런처를 지정 선호도로 실행하면 게임이 그 값을 가진 채로 시작된다.

```bat
start "Maple" /affinity 55 "C:\Nexon\Maple\GameLauncher.exe"
```

상속이 실제로 일어나는지는 보호되지 않은 프로세스(notepad)로 손자 세대까지 대리 검증했다 → `0x55` 확인.

그렇게 **실제로 P코어에 묶은 상태**에서 측정했는데도 개선이 없었다. 그래서 가설 기각.

> **성격 명시:** CPU 선호도는 OS 스케줄러에 "이 스레드를 어느 코어에 올릴지" 알려주는 표준 설정이다. 게임 메모리·로직·통신에 전혀 관여하지 않으며 게임플레이 이점도 없다. 여기서는 **성능 가설을 검증하기 위한 측정 수단**으로만 썼고, **결과는 효과 없음이었다.** 안티치트를 무력화하거나 게임 동작을 바꾸는 용도로 쓰지 말 것.

## 6. 적용한 해결책

### 6.1 RAM 32GB → 64GB (근본 해결)

- DDR4-2666 16GB × 4, 전 슬롯 동일 파트넘버
- 속도는 3600 → 2666으로 하락했지만 **용량이 압도적으로 중요**
- 페이지 폴트 제거 이득 >>> 대역폭 26% 손실

> 인텔 권고: 2DPC(채널당 2슬롯) 구성에서는 동일 파트넘버를 사용해야 목표 속도에 도달한다.

### 6.2 Windows 설정 4개 (`scripts/maple_freeze_fix.ps1`)

| 항목 | 변경 | 근거 |
|---|---|---|
| HAGS (`HwSchMode`) | 1 → **2** | GPU 스케줄링 지연 감소 |
| MPO (`OverlayTestMode`) | 미설정 → **5** | DX11 창모드 스터터링의 알려진 원인 |
| GameDVR | 1 → **0** | 백그라운드 녹화 오버헤드 제거 |
| 전원 계획 | 균형 조정 → **고성능** | 최소 프로세서 상태 5% → 100%, 클럭 램프업 지연 제거 |

RAM 48GB 이상이면 페이지파일 고정 단계는 자동으로 건너뛴다.

## 7. 남은 문제 — CPU

```
P코어 6개  vs  상시 활성 8.6 스레드
TFT 3.8 + FC온라인 2.6 + 메이플 1.0 + LeagueClient 0.9 + dwm 0.3
```

초과분이 느린 E코어로 밀린다. `core_max` 피크 98.5%.

**메이플은 DirectX 11 단일 렌더 스레드** 구조(`Gr2D_DX11.dll`, DX9 렌더러 없음)라 코어 수를 늘려도 렌더 스레드 하나가 병목이다.

### 선택지

1. **게임 3개 → 2개** — 공짜. TFT가 가장 무거움
2. **프레임타임 측정** (MSI Afterburner + RTSS) — 아직 미실시. 드랍의 정체를 확정하는 유일한 방법
3. **CPU + 보드 교체** — 14700K (8P+12E) + B760M DDR4. 현재 B660M DS3H는 6+2+1 페이즈라 253W i7을 못 먹인다. **DDR4 64GB는 그대로 사용 가능** (LGA1851/DDR5로 가면 RAM 폐기)

> 3번은 **프레임타임 측정 전에는 권장하지 않는다.** CPU 쪽으로 실행한 유일한 실험(P코어 고정)이 개선 0이었으므로, 인과가 아직 확립되지 않았다.

## 9. 측정 데이터

`data/loadlog_64gb.csv` — 64GB 증설 후 4개 동시 실행 4분 30초 기록 (26샘플)

### 알려진 서식 이슈

`Pages Input/sec` 값이 1000을 넘으면 PowerShell `N1` 서식이 천 단위 쉼표를 넣어 열이 밀린다 (26행 중 4행). 분석 시 `NF==23` 인 행은 14·15번 필드를 결합해 복원해야 한다.

```awk
if (NF==23) { pin = ($14 $15)+0; off=1 } else { pin=$14+0; off=0 }
```
